# Changelog

## Unreleased

- First real authenticated captures (a test profile on PUB400, over TLS, read-only) changed the model. `QSYS` is public `*USE` and `QGPL` public `*CHANGE`, both owned by a new `QSYS` profile; the default library list is now `QSYS QSYS2 QUSRSYS QHLPSYS`, current library, `QGPL QTEMP`; and `DSPOBJAUT` shows a basic user one `*PUBLIC` row when they have no entry of their own. The invented rule that `CRTLIB` needs `*ADD` to QSYS is gone, because a real QSYS has no public `*ADD`. The first run also showed that F3 on the real main menu does not sign off and leaves a disconnected job, so every scenario now ends with `SIGNOFF`.

- Oracle: authenticated captures. The oracle can sign on as a test profile with credentials from a gitignored, mode-600 `.env` (only `SILVERLAKE_ORACLE_*` names, never echoed). New `--tls` option verifies the certificate and host name with no way to switch that off, and a scenario that sends a password refuses cleartext beyond loopback. Values are resolved before connecting, a refused sign-on stops the run after one attempt, and the two new scenarios (`auth-probe`, `auth-libs`) only run `DSPLIBL` and `DSPOBJAUT`. `compare` replays an authenticated capture locally as a seed profile. Writing the test for the stop rule found that the first version, keyed on the terminal's error line, never fired on a real refusal, so it now looks for a message ID or a remaining password prompt.

- Phase 3c-1, commands: CRTLIB, DLTLIB, DSPLIBL, ADDLIBLE, RMVLIBLE, WRKLIB, DSPOBJAUT, GRTOBJAUT and RVKOBJAUT, built from IBM's 7.5 command pages. Each job has its own library list, and unqualified names are found through it. Revoking everything from a user removes the entry so they fall through to groups and public, which is different from holding `*EXCLUDE`. The message ladder (library not found, library locked, object not found, no authority) lets a low-authority user map what exists, on purpose. Qualified names, `*LIB` and `*FILE` objects, and single explicit names only for now. Seed `QSYS` public authority is `*CHANGE` so anyone can `CRTLIB`; that rule is inferred and flagged.

- Phase 3c-1, object model: objects are identified by library, name and type, libraries are `*LIB` objects in QSYS, and authority to an object now includes the library gate (`*EXECUTE` on the library first, `*ALLOBJ` skips it). The seed gains six libraries and three files, including `SRCLIB/QRPGSRC`, a wide open file in a locked library. Libraries, objects and authorization lists moved from one JSON row to real SQLite tables, and the seed is validated (library, owner and authorization list must exist). Deleting a profile with `OWNOBJOPT(*DLT)` takes a deleted library's contents with it.

- Phase 3b: manage users from inside a session. CRTUSRPRF, CHGUSRPRF, DSPUSRPRF, DLTUSRPRF, WRKUSRPRF and SIGNOFF work from a command line, following the IBM i 7.5 command reference: `*SECADM` to create or change, only authorities you hold can be given, `*SECADM` and `*AUDIT` need `*ALLOBJ` too. Profiles are secured objects with an owner, so a `*SECADM` user can only touch profiles they own or hold authority to, which is why `DEVADMIN` cannot change the seeded accounts. Deleting handles owned objects (`OWNOBJOPT`), group cleanup, and refuses protected or in-use profiles. Changes persist in `state/silverlake.sqlite`, and `reset.sh` wipes them. Message IDs for these commands come from IBM's lists and are marked as documented, not seen. Sessions are counted in and out, including dropped connections.

- Phase 3a: the access model. Five user classes with IBM's defaults by QSECURITY level, eight special authorities, grant rules, object authority with `*ALL`/`*CHANGE`/`*USE`/`*EXCLUDE`, authorization lists and groups. Profiles come from `data/profiles.toml` (19 seed accounts, one per class, one per special authority, plus the usual misconfigurations). Sign-on now checks the profile and answers with message IDs. A placeholder menu shows the effective access after sign-on. Found live: a profile with all eight authorities overflowed the screen and dropped the session; screens now wrap, and a failing session is logged without touching others.
- Sign-on screen moved to the stock layout, taken from a photo of a default display and the stock parts of the PUB400 capture: fields at col 52 on rows 5 to 9, info block at cols 47 and 69 on rows 1 to 3, copyright at col 39, no date line. The message-on-bottom-row behavior is unchanged.
- Phase 2: fidelity oracle. A 5250 client, host stream decoder, structural diff, and a CLI (`python -m silverlake.oracle`) with an allowlist and rate limit for non-loopback hosts. First captures from PUB400 fed back three generic fixes: monocase on the sign-on user field, fields that wrap across rows, and the bottom-row message line. Snapshots are re-derived from raw records so old captures stay comparable.
- Phase 1: 5250 core. Telnet framing, TN5250E negotiation (terminal type, NEW-ENVIRON device name, binary, EOR), GDS records, declarative screens rendered to a real data stream, sign-on screen that round-trips. Checked against web3270's tn5250 client.
- Repo scaffold: README, ROADMAP, architecture and not-faked docs, lifecycle scripts, loopback guard.
